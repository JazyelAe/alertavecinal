Flujo de una notificación push en AlertaVecinal

1 · Vecino AEnvía una alertaLa PWA la guarda en Firestore y llama a Apps Script con su idToken.
➜
2 · Apps Scriptaccion_pushVerifica la sesión, lee la alerta y los tokens, firma con la cuenta de servicio.
➜
3 · FCMFirebase Cloud MessagingAPI HTTP v1 entrega el mensaje a cada token registrado (VAPID).
⬇
6 · Vecino BToca la notificaciónnotificationclick abre o enfoca la app en la alerta.
⬅
5 · Service workershowNotification()Con la app cerrada: onBackgroundMessage muestra la notificación y vibra.
⬅
4 · Navegador de BRecibe el pushAbierta: onMessage (primer plano). Cerrada: el service worker (segundo plano).

El token FCM se obtiene una vez con getToken(messaging, {vapidKey}) después de Notification.requestPermission() y se guarda en Firestore.

Backend de «Vecino Verificado Pro» (Google Apps Script)

ClientePWA (GitHub Pages)admin.js → POST text/plain
{accion:"verificar", idToken, uid, verificado}

estadisticas.js → enlace GET
?vista=verificado&uid=…
➜
ServidorApps Script · Comun.gsdoGet → vista_verificado(e)
doPost → accion_verificar(d)

Verificado.gsvalida uid, sesión y rol admin; calcula indicadores; renderVista_ con vista_verificado.html
➜
DatosFirestore (API REST)leerDoc_, consultar_, actualizarDoc_ con token OAuth de la cuenta de servicio (guardada en Propiedades del script).

Firebase Auth valida el idToken.

Respuestas: la vista devuelve HTML generado en el servidor; la acción devuelve JSON {ok, uid, verificado} o {ok:false, error}.
